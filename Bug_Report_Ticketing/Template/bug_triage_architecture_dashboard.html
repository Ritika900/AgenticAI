detective.py

First agent in the workflow. Uses LLM to extract search keywords from the bug report, then calls GitHub issues search. Sets github_matches, needs_user_clarification, and selected_issue in state.

run_detective() extract_keywords() search_github_issues()
Deps: langchain-openai, requests · Env: GITHUB_TOKEN, GITHUB_REPO

brain.py

Second agent. Calls search_past_incidents() on Google Sheets to detect patterns, then asks LLM (Azure OpenAI) to classify priority P1–P4. Auto-escalates to P1 if ≥2 unresolved similar reports in past 7 days. Sets refined_search_needed to loop Detective if needed.

run_brain() pattern detection P1–P4 LLM classify refined_search loop
Deps: langchain-openai · Env: OPENAI_DEPLOYMENT, OPENAI_API_BASE

fixer.py

Final action agent. First checks ServiceNow for existing tickets; if found, updates them. Otherwise creates a new incident. After creation: logs to Google Sheets, adds issue to ChromaDB RAG store, and appends to Excel log. All three writes are individually try/caught.

run_fixer() search_incidents() create_incident() update_incident() log_incident() add_issue() log_to_excel()
Calls: servicenow_tool, sheets_tool, rag_store, excel_logger

rag_store.py

RAG layer. Embeds bug descriptions via Azure OpenAI text-embedding-ada-002 and stores/queries a persistent ChromaDB collection (bug_issues) using cosine similarity. Used for duplicate detection before ticket creation, and for adding new incidents after creation.

add_issue() search_similar() delete_issue() collection_size()
Deps: openai, chromadb · Env: EMBEDDING_DEPLOYMENT, CHROMA_PATH

github_tool.py

Searches a configured GitHub repo for matching open issues using the GitHub REST search API. Supports optional label filtering. Returns top 5 matches with title, body snippet, labels, and URL.

search_github_issues() label filter REST v3
Deps: requests · Env: GITHUB_TOKEN, GITHUB_REPO

servicenow_tool.py

Creates, searches, and updates ServiceNow incidents via the Table API. Returns incident_number and a direct incident_url rendered as a button in the chat UI. Priority maps directly from P1–P4 to ServiceNow urgency/impact.

create_incident() search_incidents() update_incident() get_incident_status()
Deps: requests · Env: SERVICENOW_INSTANCE, _USERNAME, _PASSWORD

sheets_tool.py

Google Sheets integration for pattern detection and incident logging. search_past_incidents() looks back N days for symptom-keyword matches and flags patterns when ≥3 similar reports exist. log_incident() appends one row per new ticket.

search_past_incidents() log_incident() pattern detection
Deps: google-auth, googleapiclient · Env: GOOGLE_SHEET_ID, GOOGLE_SHEETS_CREDENTIALS

excel_logger.py

Appends one row per resolved incident to a local .xlsx file using pandas + openpyxl. Columns: Incident Number, User Message, Priority, Incident URL. File path is configurable via INCIDENT_LOG_PATH. Also used as a RAG source (Excel + GitHub) for future lookups.

log_to_excel() openpyxl engine
Deps: pandas, openpyxl · Env: INCIDENT_LOG_PATH · File: Past Incidents Log.xlsx

app.py — Flask API + dedup cache

Flask server hosting the web chat UI and /triage + /webhook endpoints. Runs an in-memory MD5 dedup cache before forwarding to main.py. Returns cached result with duplicate: true for repeated reports. Swap _triage_cache dict for Redis for cross-restart persistence.

POST /triage POST /webhook _triage_cache _normalise()
In-memory dedup · Port 5000 · debug=True

workflow.py — LangGraph graph

Defines the LangGraph StateGraph with 5 nodes: detective → brain → rag_check → fixer → format_response. Conditional edges handle: refined-search loop (brain→detective), duplicate short-circuit (rag→format), clarification branch (detective→format). Compiled once as bug_triage_workflow.

detective node brain node rag_check node fixer node format_response
Deps: langgraph · Conditional edges via should_refine_search, needs_clarification, check_duplicate_result
